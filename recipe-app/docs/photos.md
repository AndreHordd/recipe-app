# Фотографії рецептів

До рецепта можна додати одне основне фото. Підтримуються статичні JPEG, PNG і WebP до 5 МБ (5 × 1024 × 1024 байти), до 20 мегапікселів. Фото необов'язкове для публікації. Анімовані, пошкоджені файли, SVG і GIF відхиляються.

## Через інтерфейс

У **Новий рецепт** або **Редагувати** відкрийте блок **Фотографія** та виберіть файл. З'явиться попередній перегляд. **Зберегти чернетку / Зберегти зміни** спочатку збереже рецепт, потім завантажить обране фото.

Для наявного рецепта є окрема кнопка **Завантажити фото**. Вона змінює тільки фото; інший текст у формі залишається незбереженим до натискання **Зберегти зміни**. Новий файл замінює попередній. **Скасувати вибір фото** повертає попередній перегляд поточної фотографії. **Видалити фото** потребує підтвердження.

Якщо рецепт збережено, а фото відхилено, форма покаже обидва результати та залишиться відкритою. Оберіть справний файл і повторіть **Завантажити фото**: другий рецепт не створиться. Після успішної спроби попередня помилка зникне.

Зміна або видалення фото опублікованого рецепта повертає його до чернетки. Прихований рецепт залишається прихованим. Автор не може обійти модерацію через фото. При конфлікті версії введений текст та обраний файл залишаються до підтвердженого завантаження актуальної версії.

На сторінці рецепта показується основне фото. У каталозі, «Мої рецепти», колекціях та адмініструванні використовується мініатюра. Рецепти без фото працюють як раніше.

## Збереження та доступ

Pillow перевіряє справжній вміст файла, застосовує поворот EXIF і створює нові JPEG без початкових метаданих. Довша сторона основного зображення — до 1920 px, мініатюри — до 480 px. Прозорий фон PNG/WebP замінюється білим. Початковий файл не зберігається. Використано [документацію Pillow](https://pillow.readthedocs.io/en/stable/reference/Image.html) та [ImageOps](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html).

Типова папка — `recipe-app/uploads`. Її можна змінити через `UPLOADS_DIR` у `.env`, бажано абсолютним шляхом. Папка створюється при першому завантаженні та виключена з Git. Файли мають випадкові ключі й суфікси `.jpg`, `.thumb.jpg`; початкове ім'я файла не використовується.

Міграція `002_recipe_photos.sql` додає необов'язковий `recipes.photo_key`. Застосуйте її через **Database - Prepare** або запустіть **Recipe App**: основна конфігурація перевіряє міграції автоматично. Для нового оточення встановіть оновлений `requirements.txt` або `requirements.lock`.

Папка фото не є публічною статикою. Запити фото проходять перевірку доступу до рецепта: гість бачить тільки PUBLISHED; автор — власні DRAFT/HIDDEN; адміністратор — усі. Змінює фото тільки автор, навіть якщо поточний користувач є адміністратором. Чужа чернетка повертає 404. Основне фото й мініатюра віддаються з `Cache-Control: no-store` та `nosniff`.

Нові файли готуються до запису посилання в БД. Якщо транзакція або перевірка версії не пройде, нові файли прибираються, попередні залишаються. Після успішної заміни чи видалення прибираються старі файли. Видалення рецепта також прибирає його фото. Помилка прибирання після commit журналюється й не скасовує вже успішну дію.

## Резервна копія та прибирання

Резервуйте **PostgreSQL і папку `UPLOADS_DIR` разом**, бажано із зупиненим застосунком. Файли не містяться в SQL-дампі. Без відновлення папки посилання в базі не повернуть фотографії.

Після аварійної зупинки можуть залишитися файли без посилання в рецепті. За зупиненого сайту можна спочатку переглянути список:

```powershell
.\.venv\Scripts\python.exe -m scripts.cleanup_photos
```

Для видалення перелічених файлів:

```powershell
.\.venv\Scripts\python.exe -m scripts.cleanup_photos --delete
```

Команда працює тільки з налаштованою папкою фото, файлами очікуваного формату та віком понад 24 години. Чинні ключі з PostgreSQL, свіжі файли, символічні посилання та сторонні файли залишаються.

## API

| Метод | Маршрут | Результат |
|---|---|---|
| GET | `/api/recipes/{id}/photo` | Основний JPEG або 404 |
| GET | `/api/recipes/{id}/photo?thumbnail=true` | Мініатюра JPEG або 404 |
| PUT | `/api/recipes/{id}/photo?version=N` | Бінарне тіло файла; 200 RecipeRead |
| DELETE | `/api/recipes/{id}/photo?version=N` | 200 RecipeRead; без фото рецепт не змінюється |

PUT передає байти файла з `Content-Type: image/jpeg`, `image/png`, `image/webp` або `application/octet-stream`; multipart і JSON тут не використовуються. Сервер обмежує фактично отримані байти навіть без `Content-Length`. Обидві зміни потребують cookie, Origin та `X-CSRF-Token`. Формат заголовка не замінює перевірку вмісту.

У RecipeRead і RecipeSummary додано `photo_url`, `thumbnail_url` або `null`. Внутрішній ключ не повертається клієнту. Параметр `v` у URL оновлює адресу зображення після зміни версії; права перевіряються при кожному запиті.

Помилки: 413 `PHOTO_TOO_LARGE`, 422 `INVALID_PHOTO`, 415 `PHOTO_FORMAT_REQUIRED`, 404 `PHOTO_NOT_FOUND`, 503 `PHOTO_STORAGE_UNAVAILABLE`, 409 `VERSION_CONFLICT`. Якщо файла на диску вже немає, повертається 404 без внутрішнього шляху.
